# 版本更新檢查清單

每次版本更新或重新封裝時，依此文件檢查，避免安裝包、更新資訊、網站與操作文件不一致。以下以 `1.5.1` 為例，發布其他版本時請替換版本號。

## 必須同步的檔案

| 檔案 | 檢查與更新內容 |
| --- | --- |
| `Directory.Build.props` | 將 `Version` 設為本次版本，確認程式與安裝包版本一致。 |
| `docs/v<版本>發布說明.md` | 記錄本次最終功能、修正、操作變化及安裝升級說明；重新封裝也要補上新增變更。 |
| `version.json` | 更新 `latestVersion`、GitHub Releases 安裝包 `downloadUrl`、最終安裝包的 `sha256`，以及與發布說明一致的 `releaseNote`。 |
| `index.html` | 更新版本標示、所有下載連結、發布說明連結、更新摘要，以及 JSON-LD 的 `softwareVersion`、`releaseNotes`、`downloadUrl`；功能區與常見問題也要符合新行為。 |
| `README.md` | 更新目前版本、下載連結、改版摘要及受影響的主要功能說明。 |

## 依變更內容同步的檔案

| 檔案或位置 | 何時需要更新 |
| --- | --- |
| `docs/使用指南.md` | 操作流程、通知行為、按鈕、設定或功能限制改變。 |
| `docs/安裝教學.md` | 安裝、升級、下載或系統需求改變。 |
| `docs/管理員JSON設定匯入.md`、設定範本與 `Sheet範例/` | 管理設定、JSON 欄位或試算表格式改變。 |
| `docs/健康工具.md` 等專題文件 | 對應功能或限制改變。 |
| `docs/驗收清單.md`、`docs/問題與優化追蹤.md` | 驗收條件、既有問題或預期行為改變；已完成狀態須有實際驗證支持。 |
| `docs/常用CLI指令.md`、`scripts/publish.ps1`、`installer/` | 建置、封裝、安裝流程或版本參數規則改變。腳本預設值與範例版本不必每次機械替換。 |
| `src/` 中的介面文字與對應測試 | 提示、預覽、設定描述或測試仍保留舊行為。 |
| `site-assets/screenshots/` | 公開畫面已與實際介面明顯不符，需重新截圖。 |
| `sitemap.xml` | 網頁更新且有維護 `lastmod` 時，同步實際修改日期。 |

歷史發布說明保留當時內容。「某功能自 v1.5.0 起提供」等歷史版本資訊也應保留，避免全部搜尋取代。

## 建置與發布順序

1. 完成功能修改，執行適合此次變更的建置、測試與人工操作驗證。
2. 更新版本設定、發布說明、README、首頁與受影響的操作文件。
3. 封裝指定版本：

   ```powershell
   ./installer/build-installer.ps1 -Version 1.5.1
   ```

   封裝腳本要求版本高於 `version.json` 的已發布版本，因此新版本應先封裝，再更新更新資訊。若明確要求重封同版本，先檢查腳本限制與既有產物，勿為通過檢查而降低公開版本資訊。

4. 確認產物為 `artifacts/installer/CloudAlarmOverlay-v1.5.1-Setup-x64.exe`，並計算最終雜湊：

   ```powershell
   Get-FileHash -LiteralPath artifacts/installer/CloudAlarmOverlay-v1.5.1-Setup-x64.exe -Algorithm SHA256
   ```

5. 將最終安裝包上傳至對應的 GitHub Release，確認下載網址、檔名與版本正確；有重新封裝時，必須重新計算雜湊，並確認上傳的是同一份檔案。
6. 更新 `version.json` 的版本、下載網址、SHA-256 與發布說明。可下載遠端安裝包重新計算雜湊，確認與更新資訊一致後再公開。
7. 檢查文件與網站，確認沒有殘留不適用的舊版本下載連結或舊行為文案：

   ```powershell
   rg -n '1\.5\.0|自動關閉|10 秒' README.md index.html version.json docs
   git diff --check
   git diff --stat
   git status --short
   ```

   搜尋詞依本次版本與功能調整；逐項判斷結果，不要修改仍正確的歷史敘述。

8. 確認 `version.json` 與首頁 JSON-LD 可解析、下載連結正確，並檢查安裝與更新流程。
9. 依本次授權範圍提交及推送變更；若要求中英文 commit，兩種語言皆需描述最終變更，且遵守使用者指定的署名限制。

## 發布前最後確認

- [ ] 程式版本、安裝包檔名、Release 標籤、首頁與更新資訊一致。
- [ ] SHA-256 對應最終公開安裝包，重新封裝後沒有沿用舊雜湊。
- [ ] README、發布說明、首頁功能文案與操作指南描述一致。
- [ ] 通知按鈕、置頂、自動關閉與完成狀態等行為已逐項核對。
- [ ] 建置與必要驗證通過；未驗證的項目如實註明。
- [ ] 已確認提交內容，沒有誤加入金鑰、個人設定或不應追蹤的產物。
