## 功能進度與構想

### Google 帳號與 Sheets 同步大改

> CAO-028｜v1.4.0 已開始分階段實作，下列保留完整目標設計，不代表每項延伸皆已完成。已接上多帳號登入、私人 Tasks／自有日曆讀取、憑證續用、來源分頁與受控 Tasks 寫回；真實 Google 登入尚待用戶端設定後驗收。

**本機版交付範圍**：目前新 Google 來源支援 Tasks 與自有日曆，原 A／B 公開來源獨立保留；尚未做原來源身分直接遷移、員工／假日／農曆 Google 來源、產生器寫回橋接、共享日曆及增量同步。操作方式與限制以 [Google 帳號與同步設定](Google帳號與同步設定.md)為準。

**目標與現況**

目前同步來源固定為 Sheet A／B，透過公開 CSV 讀取，不會使用瀏覽器已登入的 Google 身分。因此「瀏覽器能看、程式讀取失敗」須區分登入權限與暫時連線錯誤。改版後提供 Google OAuth 授權，讓已分享給登入帳號的私人試算表能同步，不必公開；保留既有公開 CSV 模式及離線快取。

本規劃的「表單」指 Google Sheets 試算表；Google 日曆唯讀同步與本機提醒納入本次大改。Google Forms 問卷編輯與提交、Google Calendar 雙向同步另案評估。OAuth 也不保證網路永不逾時，仍須保留錯誤分類與重試。

**帳號登入與權限**

- 使用系統瀏覽器進行桌面 OAuth 授權，採 PKCE、`state` 驗證及本機 loopback 回呼；程式不收集 Google 密碼或讀取瀏覽器 Cookie。Refresh token 以 Windows 使用者範圍加密保存，不進 Git、安裝包、一般設定匯出或日誌。桌面用戶端不能把隨程式配送的 client secret 當作可保密憑證。[官方桌面 OAuth 說明](https://developers.google.com/identity/protocols/oauth2/native-app)
- 支援多帳號同時維持登入，例如公司 Workspace 與個人 Gmail；提供「新增 Google 帳號」、自訂公司／個人標籤、個別重新授權、登出與解除授權。切換畫面上的帳號篩選不會登出其他帳號，也不會停止其他帳號背景同步。
- 每個 Sheet／日曆來源綁定明確的帳號識別；憑證、授權範圍、快取與同步狀態各自隔離，不用單一全域「目前帳號」決定請求身分。同一帳號重複登入應更新既有連線，避免重複建立來源；一個帳號授權失效不影響其他帳號。
- **憑證有效就能自動續用**：預設保持登入，依 Google 回傳的存取憑證期限，在背景使用有效的更新憑證取得新憑證；重啟程式後仍可續用，不自行設定每隔幾天強制重新登入。各帳號獨立更新，與本機公司模式管理員的 10 分鐘登入期限分開。[Google 憑證更新機制](https://developers.google.com/identity/protocols/oauth2/native-app#offline)
- 只有確認更新憑證失效、到期或授權遭撤銷時，才將該帳號標示為「需要重新登入」，由使用者操作後開啟瀏覽器；網路逾時或暫時性服務錯誤保留憑證並有限重試。公司政策封鎖另顯示需管理員處理，避免反覆要求登入。自動續用不保證永久有效；外部 Testing 專案的 Sheets／日曆授權更新憑證通常 7 天到期，正式使用須處理發布狀態及 Google 的到期規則。[憑證失效條件](https://developers.google.com/identity/protocols/oauth2#expiration)
- 個別登出停止該帳號同步與私人來源提醒、清除本機憑證；解除授權另向 Google 撤銷。私人快取預設清除，歷史保留去識別的提醒狀態；若允許離線保留須明確告知與提供清除入口。來源改綁帳號時重新驗證權限並重建快取，不沿用前一帳號的私人內容。
- 初期唯讀評估 `spreadsheets.readonly`；它的授權範圍涵蓋帳號可存取的試算表，不能宣稱只授權貼上的單一網址。另評估 `drive.file` 搭配選檔流程縮小至指定檔案；單純貼上網址不等於已授予應用程式檔案存取權。寫回階段須確認 scope 與檔案編輯權限，必要時重新授權；桌面流程不可直接假定支援增量授權。[Sheets scopes](https://developers.google.com/workspace/sheets/api/scopes)、[桌面授權限制](https://developers.google.com/identity/protocols/oauth2/native-app)
- 個人／公司使用模式沿用目前設計：個人模式管理功能免密碼，公司模式仍需本機管理者登入。Google 登入只代表雲端身分，不自動授予本機管理者、Workspace 管理員或 Sheet 編輯權限。
- 寫回必須同時符合本機操作權限、OAuth 授權、檔案／範圍權限及來源寫入開關。檢視者只能讀取；保護範圍拒絕寫入時顯示原因，不嘗試繞過。

**同步來源介面：Pill Tabs**

- 「管理者專區 → 同步來源」改為兩端半圓、滑動動畫的 Pill Tabs；第一頁為「總覽」，後續每個來源一頁，提供「＋新增來源」。來源多時可水平捲動，切換保留尚未儲存的草稿。
- 總覽以卡片顯示來源名稱、來源類型（Sheets／Google 日曆／公開 CSV）、綁定帳號、公開／登入授權、唯讀／可編輯、最後成功同步時間及錯誤原因；提供全部同步、依帳號同步與個別同步，以及「全部／公司／個人」帳號篩選。
- 每個來源可設定名稱、存取方式、帳號、試算表網址／ID、工作表對應、啟用狀態及同步頻率；貼網址解析 spreadsheet ID／GID，再讀取工作表清單供選擇。
- 區分來源用途：任務、員工、假日、農曆；資料仍須符合本程式欄位格式，不把任意試算表自動視為有效任務表。重複資料與優先順序須明示，避免來源排列順序暗中改變結果。
- 保留「鎖定來源設定」防誤改；刪除來源須確認影響的快取與排程。自訂私人來源提供「取消變更／還原上次儲存」，不能套用日曆 JSON 的固定預設網址。

**Google 日曆讀取與提醒**

- 每個已登入帳號都可獨立啟用「Google 日曆」，列出該帳號的主日曆與自己建立的其他日曆，勾選要同步的日曆後儲存。公司與個人日曆可同時顯示，不需公開日曆或貼上私人 ICS 網址。
- 日曆使用獨立的 Calendar API 授權，已授權 Sheets 不代表已授權日曆；可只用 Sheets、只用日曆或兩者並用。讀取自己的日曆優先評估 `calendar.calendarlist.readonly` 加 `calendar.events.owned.readonly`；若後續加入他人分享的日曆，再評估 `calendar.events.readonly`。UI 勾選只限制程式同步哪些日曆，不代表 OAuth scope 本身限於勾選項目。[Google Calendar scopes](https://developers.google.com/workspace/calendar/api/auth)
- 每個日曆來源可設定顯示名稱、顏色、啟用狀態、提前提醒分鐘數、提醒等級及全天事件的本機提醒時間；第一版採本程式的提醒設定，避免不明確地疊加 Google 原有多組通知。Google 自己發送的通知仍由使用者在 Google 端管理。
- 首頁與「我的任務」可合併顯示各帳號行程，保留帳號／日曆標籤並提供篩選。項目維持來源唯讀，可開啟 Google 日曆原始事件；在本機確認提醒不會回覆邀請、修改或刪除雲端行程。
- 正確處理時區、夏令時間、全天與跨日事件、重複事件及單次例外。雲端改期時重算尚未觸發的提醒；取消／刪除或已拒絕的行程停止提醒；首次同步只排未來提醒，過去行程不大量補跳。僅有忙碌權限時不得推測私人標題或內容。[事件讀取規格](https://developers.google.com/workspace/calendar/api/v3/reference/events/list)
- 快取按帳號、calendar ID 與事件／重複實例識別隔離，重複同步與重啟不得重複提醒。若未來同一共享日曆經不同帳號接入，提示選擇主要提醒來源；不同日曆的同名活動不只憑標題自動合併。
- 初版定期讀取可設定的未來時間範圍並完整處理分頁，成功取得整個範圍才更新快取；後續可採每個帳號／日曆獨立的 `syncToken` 增量同步。Token 過期收到 410 時只重建該來源，保留提醒確認識別；增量參數不得直接混用滾動的 `timeMin`／`timeMax`。[增量同步](https://developers.google.com/workspace/calendar/api/guides/sync)、[查詢參數限制](https://developers.google.com/workspace/calendar/api/v3/reference/events/list)
- 工作區使用模式與帳號標籤分開：標記為「公司帳號」不會切換本機個人／公司模式。企業若封鎖 Calendar API 或個人帳號接入，明確顯示政策限制，不改用其他帳號繞過。

**程式內編輯與寫回**

- 第一版寫回限 `Tasks`：檢視、新增、修改、停用及刪除；員工、假日、農曆維護列後續階段。公開 CSV 來源維持唯讀，Google 來源預設也只同步讀取，使用者主動開啟寫入。
- 編輯器顯示來源、帳號及實際權限；送出前預覽差異，寫入成功後回讀並更新本機快取。維持原始欄位、說明列、其他資料與公式，不整張覆蓋。
- 使用穩定任務 ID 定位並在送出前重新定位資料列，避免排序／插列造成寫錯列。以讀取快照比對偵測衝突，遇到他人修改時要求重新載入或人工合併。
- 「送出前再讀」仍有讀寫間競態，不能當作跨客戶端原子鎖；第一版限定受控編輯流程，若要保證多人同時寫入不互相覆蓋，須先完成可驗證的序列化寫入方案。
- 逾時造成結果不明時先依操作識別與任務 ID 回讀確認，避免盲目重送新增造成重複；離線只保留草稿，不自動排隊回寫。稽核記錄操作者、來源、時間及變更摘要，遮蔽憑證與私人內容。
- 任務產生器未來可接入相同的寫入服務；OAuth token 留在桌面端，不傳給瀏覽器頁面。本機橋接須驗證呼叫來源與工作階段，避免任意網站代發寫入。

**同步架構、錯誤與相容性**

- 將來源設定由固定 A／B 擴充為來源集合，分離公開 CSV 與 Google Sheets API 讀取器；登入憑證、同步快取與寫入服務各自管理。快取與任務識別納入來源及帳號，避免不同 Sheet 的相同任務 ID 互相覆蓋。
- 升級自動遷移既有 Sheet A／B 設定，保留來源身分、歷史、釘選、提醒確認及既有資料優先順序；未登入仍可沿用公開來源。不要求使用者重新建表，資料庫與備份格式變更須有遷移驗證。
- 分別顯示網路中斷、憑證失效、權限不足、來源不存在與格式錯誤；無權限不可偽裝為空表或自動改用公開端點。一般網路失敗保留上次成功快取並標示過時；確認權限撤回時停止該私人來源的排程並依清除政策處理。
- 多來源採批次讀取、限制並行及依帳號／專案統籌頻率；429、暫時性服務失敗使用有限次數退避與隨機延遲，憑證無效或權限不足不無限重試。多人共用 OAuth 專案的配額需先試算，不直接把現有 45 秒輪詢複製到每一個來源。[Sheets API 配額與退避](https://developers.google.com/workspace/sheets/api/limits)
- GitHub 日曆 JSON 更新維持獨立，不要求 Google 登入；Google 整合故障不得阻塞本機提醒、健康工具或番茄鐘。

- **現況**：公司或個人行事曆（Google 日曆、Outlook）的會議與行程，須在本程式重複建立才能收到提醒。
- **構想**：在設定新增「行事曆訂閱」，貼上 ICS 訂閱網址（Google 日曆的「iCal 格式私人網址」、Outlook 的「發佈行事曆」連結），程式定期讀取，自動在事件前提醒。
- **設定項目**：訂閱名稱、網址、提前提醒時間（例如 10 分鐘前）、提醒等級（一般或重要）、全天事件是否提醒、啟用／停用。
- **顯示**：行事曆事件在「我的任務」與首頁以「行事曆」來源標示，唯讀不可編輯；可依訂閱整批停用。
- **更新**：每 15–30 分鐘重新讀取；事件新增、修改、刪除會同步反映。讀取失敗時保留上次結果，並在側邊欄狀態顯示該訂閱異常。
- **注意**：
  - ICS 需處理重複規則（RRULE）、例外日期（EXDATE）、時區與全天事件，建議使用成熟套件（例如 MIT 授權的 Ical.Net），新增套件須更新 `packages.lock.json`。
  - 私人 iCal 網址等同存取權，只存在本機；介面與日誌中遮蔽顯示，備份時提示是否包含。
  - 只讀取、不寫回外部行事曆。
  - 與既有的「行事曆（ICS）匯出」構想方向相反，可共用 ICS 解析與產生元件。

### 錯過提醒摘要

- **現況**：關機或休眠期間錯過的通知只寫入歷史紀錄，不會補跳。
- **構想**：開機或喚醒後，在系統匣或首頁顯示一則「你錯過了 N 則提醒」的摘要，列出清單，可逐筆確認或一次標記已讀。
- **注意**：只摘要、不補跳個別通知，避免開機時一次跳出一大堆視窗。

### 多螢幕顯示緊急與強制通知

- **現況**：`AlarmWindow` 依主螢幕尺寸定位，緊急與強制通知只出現在主螢幕。
- **構想**：強制通知在每個螢幕都顯示遮罩，確認碼輸入框放在主螢幕；緊急通知可選擇顯示在滑鼠所在的螢幕。
- **注意**：需驗證不同 DPI 縮放的多螢幕組合。

### 確認回報集中查看

- **現況**：確認紀錄只存在各台電腦，管理者無法集中看到誰已確認強制通知。
- **構想**：用 Google Apps Script 網頁應用程式或 Google 表單接收確認結果，寫入 Sheet C，讓管理者看到每則通知的完成率。
- **注意**：這會改變目前「程式不回寫雲端」的設計原則，需要評估隱私、公司政策與網路失敗重送機制，建議預設關閉。

### 程式內自動下載更新

- **現況**：程式讀取 `version.json` 檢查版本，下載則交給瀏覽器，使用者要自己執行安裝檔。
- **構想**：程式直接下載安裝檔，比對 `version.json` 中的 SHA-256，驗證無誤後詢問是否立即安裝。
- **注意**：雜湊不符時必須拒絕執行；下載來源限定 GitHub Releases 網域。

### 快速新增與任務範本

- **現況**：新增任務須開啟主視窗並填寫完整表單。
- **構想**：加上全域快捷鍵，開啟精簡的快速新增視窗；常用任務（例如每月報表、週會）可存成範本，一鍵套用。
- **注意**：快捷鍵要能自訂，並偵測是否與其他程式衝突。

### 行事曆（ICS）匯出

- **構想**：將本機任務與倒數事件匯出為 `.ics`，匯入 Outlook 或 Google 日曆。
- **注意**：農曆與「假日略過」規則無法完整轉成 ICS 的重複規則，可改為展開未來一年的個別日期。

### 番茄鐘綁定任務

- **構想**：開始番茄鐘時可選擇對應的任務，統計每個任務累積的專注時間，歷史紀錄可依任務篩選。

## 優化構想

### 每月農曆改用內建曆法

> ✅ 已實作，已納入本機 v1.3.0 安裝檔。農曆由 .NET 內建 `ChineseLunisolarCalendar` 換算；節氣繼續使用 Sheet A 的 `LunarCalendar`。

- **提醒排程**：每月初一／十五等日期、每年指定農曆月日，皆在本機計算。任務、倒數、預覽與分享圖片使用相同規則，不受 Sheet 農曆欄缺漏或錯誤影響。
- **首頁顯示**：今日與下一次提醒的農曆直接換算；節氣仍讀取 `LunarCalendar.SolarTerm`，無資料時顯示「-」，讀取失敗時顯示暫不可用。
- **閏月與日期**：每月農曆包含閏月；每年農曆沿用是否包含閏月的選項。小月沒有三十時略過該月，不改成月底提醒；超出內建曆法範圍不猜日期。
- **相容性**：保留既有 `LunarDay:`／`LunarDate:` 規則、Sheet 分頁、GID 與 CSV 欄位，不需重建任務或資料庫遷移；舊農曆對照欄位不再參與排程。
- **驗證**：2026–2027 既有 730 筆農曆日期逐日比對一致；涵蓋閏月、三十、小月、2028 年無對照資料與支援範圍邊界。
- **仍需維護**：Sheet 的節氣、國定假日及補班日。這次未改為內建節氣計算。

### 任務產生器離線化

- **已實作**：Tailwind 預編譯 CSS、固定版本 Lucide、SheetJS 與三套字型皆改由 `task-builder-assets` 提供，隨程式建置與發佈配送，不再依賴 CDN。
- **雲端資料為輔助**：Google Sheet 任務與員工名單讀取失敗，仍可手動新增、編輯目標／排除對象，並匯出 Excel／CSV；未載入的雲端編號無法檢查重複。
- **驗證**：瀏覽器阻擋外網、模擬 Sheet 讀取失敗，驗證本機 HTTP 與直接開啟 HTML 均可操作；本機服務測試包含資源類型與不合法路徑。
- **維護**：資源約 5.5 MiB，版本、授權及重建流程見 [資源說明](../task-builder-assets/README.md)。修改 Tailwind class 後須重新產生 CSS；此變更已納入本機 v1.3.0 安裝檔。

### GitHub Actions 自動測試

- **現況**：儲存庫沒有 CI，測試靠手動執行。
- **構想**：推送或建立 PR 時，在 `windows-latest` 執行 `dotnet test`；另可在建立標籤時自動建置發布檔。
- **注意**：WPF 測試需要 Windows runner；截圖類測試可能要另外處理。

### 日誌自動清理

> ✅ 已實作，已納入本機 v1.3.0 安裝檔。

- **預設**：保留最近 30 個本機日曆日（含今天）的 `logs/runtime-yyyyMMdd.log`，按檔名日期判斷；今天與未來日期不刪除。
- **管理者設定**：「管理者專區 → 本機設定 → 日誌自動清理」，可輸入 1–365 天並儲存，無須重啟。
- **執行時機**：資料庫初始化後啟動檢查，之後每小時檢查；設定修改於下次檢查生效，最晚一小時內。
- **範圍**：僅處理日誌資料夾直屬且名稱／日期合法的 runtime 日誌，不遞迴子資料夾、不跟隨連結；不刪除任務歷史、同步紀錄、稽核紀錄、資料庫或備份。
- **失敗處理**：被占用或無權限的檔案略過，下次再試；不影響提醒。未設定或舊資料值無效時回到 30 天。
- **部署**：管理員 JSON 匯入／匯出及通用範本支援 `RuntimeLogRetentionDays`；省略時保留原設定。保留天數的修改寫入操作稽核。

### 自動備份排程

- **現況**：備份須由管理者手動建立。
- **構想**：每週或每次升級前，自動在本機建立 `.calbak`，保留最近 N 份；升級安裝前先備份，降低資料庫遷移失敗的風險。

### 移除未使用的占位服務

- **現況**：`HolidayService`、`LunarScheduleService`、`OverdueGraceService` 是 Milestone 0 占位實作，呼叫即拋例外，仍在 DI 註冊但沒有程式使用；實際判斷已在 `TaskSchedulingService`。
- **構想**：移除三個類別、介面與註冊，減少誤用風險。

### 首次登入強制變更預設管理者密碼

- **現況**：新資料庫預設帳密 `admin`／`12345`，且公開於 README，只提醒使用者自行變更。
- **構想**：以預設帳密登入時，須先設定 8–128 字的新密碼才能進入管理者專區；已變更密碼的電腦不受影響。
